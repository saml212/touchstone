# v3 Stage 6 — the UI over touchstone/ + Harbor job dirs (five pages)

Contract: `docs/DESIGN.md` (server: Overview, Tasks, Trials, Review, Train) + stage6-brief.
Builds on stage-4 review room (`review/*`, `server/routes/rooms.py`, `server/static/room.*`) and
stage-5 train (`train/*`). One server (`touchstone serve`), vanilla JS, existing aesthetic, phone
width. Every page reads files at request time; JSON routes under `/api/pages/*` tested with the
FastAPI test client on a fixture dataset.

## Facts learned (verified this session)
- `app.py` serves `static/index.html` at `/`; current `index.html`+`app.js` are v2-era (nav to
  checks/benchmarks/mine, routes that no longer exist). Replace both with the five-page shell.
- `/api/overview` + `/api/episodes` (trace-DB counts) stay — `test_server_api` depends on them.
- Data sources, all file-reads at request time:
  - `review/trials.py`: `scan/read/needs_review/counts`, `TrialRef`; `read(dataset,jobs,task,tid)`
    gives instruction (canary-stripped), trajectory transcript lines, criteria (plain desc+score).
  - `harbor/jobs.py`: `Job.read`, `pass_rates`, `mean_rewards`, `Trial`.
  - `review/agent.py` module fns reusable: `_job_labels`, `_baseline_counts`, `_join`,
    `_task_count`, `_read_toml`, `_touchstone_meta`.
  - `survey/descriptions.py`: `load(tests_dir)`, `key(rel,idx)` — plain-English criterion labels.
  - dataset files: `groups.json` (episodes per job-to-be-done → conversation count), `baseline.json`
    (pass_rates/passed → K passes), `fidelity.json` (services + score/reproduced/status),
    `report.md` (map), `tasks/<t>/{task.toml,instruction.md,persona.md,tests/*}`,
    `train/manifest.json` (route counts, inputs).
- Config: `settings.review_dataset_dir` (root/touchstone) + `settings.review_jobs` (dataset/jobs).
- Room preload: `POST /api/rooms {task_id}` opens a review room; navigate to `/rooms/{id}`
  (existing page). Do not rebuild the room.

## Design decisions (simpler option, noted)
- New data module `server/pages.py` (pure fns, file-reads) + thin router `routes/pages.py` under
  `/api/pages/*`. Overview lives at `/api/pages/overview` (distinct from trace `/api/overview`).
- Labels come from the dataset (job-to-be-done from `[metadata.touchstone].job`, group labels,
  descriptions.toml) — never hard-coded product words.
- Review nav = list existing rooms + "start a review" button (reuses room page). Trial page
  "review this trial" = `POST /api/rooms {task_id}` → `/rooms/{id}`.
- Train page: route counts + manifest + copyable `touchstone train …` command. No Run button —
  stage 5 exposes only the CLI, no server run route (noted).
- Empty dataset → each route returns empty/empty-flag data (200), never 500.

## Routes (`/api/pages/*`)
- `GET /overview` — sentence, map paragraph, services+fidelity, tasks-by-job counts, latest job per
  agent/model, trust (if reviews).
- `GET /tasks` — [{task, job, criteria[], gate{oracle,nop}, rewards{model:reward}}].
- `GET /tasks/{name}` — instruction, persona, criteria(weights+desc by dimension), trials[].
- `GET /jobs` — job picker [{job, date, agent, model, tasks, passed}].
- `GET /jobs/{job}` — per-task rewards for one job.
- `GET /trial?task=&trial=` — reuse `trials.read`.
- `GET /train` — counts per route, manifest, command line, files-present flag.
