## Facts learned from Harbor 0.23 source + rewardkit 0.2.1 (verified)
- Docker build context = the task's `environment/` dir (`context_dir = environment_dir`,
  `Dockerfile = environment_dir/Dockerfile`). A Dockerfile CANNOT `COPY ../../`. So a shared
  environment must be a prebuilt image referenced by `[environment].docker_image`, OR duplicated
  per task. Chosen: **shared prebuilt image** built on the harbor host; every task.toml sets
  `[environment].docker_image = <tag>` (no per-task environment dir; avoids N-fold repo copies).
- Harbor OVERRIDES the container command with `sleep infinity` (docker-compose-build/prebuilt.yaml).
  So the image ENTRYPOINT/CMD never runs. Simulators must be started by `solve.sh` (oracle); the
  nop agent starts nothing → no state.db → verifier fails → nop < 1.0.
- Oracle agent (`agents/oracle.py`) uploads `solution/` to `/solution`, runs `solve.sh`, writes
  `oracle.txt`. It writes NO trajectory.json. So trajectory criteria pass for the oracle only if
  solve.sh writes `/logs/agent/trajectory.json` itself. nop writes none → trajectory absent.
- `rewardkit.sqlite_query_equals(workspace, db_path, query, expected)`: `target = workspace/db_path`
  (workspace=/app), `row = conn.execute(query).fetchone(); return row[0] == expected`. Missing db →
  False. So query must SELECT one column; expected compared to first cell.
- `trajectory_tool_used(tool_name, min_count, path=/logs/agent/trajectory.json)`: reads ATIF,
  counts steps' `tool_calls[].function_name == tool_name`. Missing file → False.
- Default rewardkit aggregation is weighted-mean → oracle needs EVERY criterion=1.0 to reach 1.0;
  nop fails ≥1 → <1.0. jobs.py `_scalar` uses "reward" key, else mean of dimension scores.
- `import touchstone` pulls NO third-party modules → vendoring the package via PYTHONPATH needs no
  extra deps. `touchstone-bench` is NOT on PyPI and the example depends on it via git+ssh (unresolvable
  offline) → the shared image vendors the touchstone package (PYTHONPATH) so `import agent` works.

## Design decisions (simpler option chosen, noted per brief)
- **Environment = one shared prebuilt image.** environment.py writes `touchstone/environment/`
  {repo snapshot (excl .git/.touchstone/touchstone/.venv/secrets), simulators/ (excl state.db,
  .sim.log), _touchstone/ vendored pkg, requirements.txt (deps minus VCS/URL/path), Dockerfile}.
  gate.py builds it on the harbor host, tags `touchstone-env-<name>-<hash>`.
- **Per-task seed = the stage-2 shared seed baked into the image** (each recorded order is at its
  recorded initial state; tickets/emails empty). solve.sh `/__reset`s then replays. No per-task seed
  files (simpler; the target order is isolated by the verifier query, not by a minimized seed).
- **solve.sh (oracle)** starts each simulator on 8000+idx, waits health, resets, exports every
  service base_url_env to its local port, runs `python -m touchstone.survey.replay spec.json`
  (REAL tool functions), then copies the pre-generated scrubbed trajectory.json → /logs/agent and
  output.json → /app.
- **Criteria derived by state diff:** tasks.py starts the sim locally, resets, dumps state.db,
  replays the (scrubbed) episode calls, dumps again, diffs. Changed non-volatile cells → sqlite
  criterion; added rows → COUNT by an input-matching column. Plus trajectory_tool_used per tool the
  episode used, trajectory_tool_not_used for a resolved-elsewhere tool it must avoid, and a no_pii
  safety criterion on output.json only when the scrubbed answer itself has no PII (else oracle fails).
- Per-episode fidelity re-check happens in the same replay: a mismatched call → episode skipped +
  listed (edge case).
