## Verified facts (from source, this session)
- `capture/spans.instrument_create`/`instrument_acreate` is the single call-through for openai chat,
  openai responses, and anthropic `messages.create`; `patch_anthropic.stream()` and litellm are the
  other SDK entrypoints. So one `override_model(kwargs)` helper, invoked at those call-through points.
- Harbor awaits `agent.setup(environment)` before `agent.run(instruction, environment, context)`
  (trial.py:1666). `environment.exec(command, cwd, env, timeout_sec, user)` — **no stdin param**, so
  the instruction is piped: `printf %s <shquoted> | bash /app/agent/run.sh`.
- Inside the sandbox `/logs/agent` == host `<trial>/agent` == `self.logs_dir` (bind mount): the
  customer db written to `/logs/agent/touchstone.db` is readable at `self.logs_dir/touchstone.db`.
- `touchstone.trace()` reads db from `TOUCHSTONE_DB` env (config `_ENV_KEYS`), so the packaged env
  points the customer's own capture at `/logs/agent/touchstone.db`.
- ATIF surfaces tool calls from the model span's assistant `tool_calls` even when the customer never
  used `@touchstone.tool` — so "≥1 tool call" = a model span whose output message has tool_calls.
- Simulators must be started by the agent (Harbor overrides CMD with `sleep infinity`); a
  `setsid nohup … &` in one exec survives later execs. base_urls are fixed (8000+idx).
- `env_result` = {deps_ok, deps_reason, ports{name:8000+i}, base_url_envs{name:env}, image_tag,
  services}. map.json has `schemas`{tool:schema}, `tools`[{name,import_path}], `model_call.sdk`.

## Design decisions (simpler option chosen, noted per brief)
- **One `override_model(kwargs)`** in capture/spans.py; called in `instrument_create`,
  `instrument_acreate`, `patch_anthropic.stream()`, and litellm's wrapped `completion`/`acompletion`.
- **`replay --one <import:fn> '<json>'`**: one call, print the JSON result. base_url comes from the
  process env (set by the caller), not an arg.
- **Simulators baked base_urls**: `tools.py` (replica) hardcodes `_BASE_URLS` (8000+idx) and passes
  them as the exec `env`; `agent.py.setup` reads `[[agent.simulator]]` from agent.toml and starts each
  on its fixed port. Both derive from the same env_result ports → consistent, no runtime coordination.
- **agent.toml**: `[agent] system max_steps mode model_default provider` + `[[agent.simulator]]`.
  `system` + `model_default` come from the recorded model spans (full system text, most-common model
  id), not the 200-char map excerpt. `provider` = map `model_call.sdk`.
- **Packaged trajectory** imported from the customer db (last episode with spans); missing → raise
  with the run.sh output tail. Replica keeps the tempdir-db model loop unchanged.
- **entry.py** generated by the survey provider (reads the repo); adapter check runs it locally
  (`uv run --project <repo>` or `[survey] python`) with the sim up, TOUCHSTONE_MODEL unset, the first
  recorded user turn on stdin → must exit 0 and record ≥1 tool call. Fail → retry once → replica+flag.
- **Key forwarding**: run.py resolves the provider key on the laptop (env/Keychain) and passes it
  over ssh **stdin** (`read -r TS_KEY; export VAR="$TS_KEY"`) remotely, or the subprocess `env`
  locally. Never argv, never printed. Only for custom agents whose model provider needs a key.
- **Baseline** runs the packaged-or-replica agent at `provider/model_default` over touchstone/tasks,
  one trial/task; writes baseline.json {job_dir, model, mode, pass_rates, passed, failed}. When it
  runs, the survey's final line IS the DESIGN sentence.
