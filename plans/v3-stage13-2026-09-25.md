# v3 stage 13 — deterministic seeding for db services

A model must never be the source of seed DATA. It may only decide WHERE the data is. Stage 12 asked
the survey provider to write the db simulator's documents/rows; on tau-bench retail (~2 MB of JSON)
claude-cli could not reproduce ~30 exact documents in one answer, so fidelity stalled at 0.19. This
stage seeds `state.db` deterministically in touchstone from real sources and never from the model.

## Contract (general; nothing target-specific in `touchstone/`)

1. **Seed sources, in order; first that applies wins; the report names the source per service.**
   a. **Data files in the repo.** The map gains an optional `"data_files": ["<path>", ...]` per
      service (MAP_PROMPT asks in one sentence). Each file is copied verbatim — scrubbed — into
      `simulators/<name>/source/` and `state.db` is materialized from it deterministically: a JSON
      dict-of-docs → a document table `(id TEXT PRIMARY KEY, doc TEXT)`; a JSON list with an `id`
      field → a document table; a CSV → a relational table with TEXT columns; a SQLite file → copied
      as `state.db`. The table/collection name is the file stem.
   b. **Recorded reads.** Otherwise every document/row a tool returned (scrubbed) keyed by the id it
      was called with or the id field in the result becomes a document table.
   c. **Provider-written seed** only when a and b yield nothing, capped and labelled `synthetic`.
   Scrubbing runs on the copied files' contents too (names/emails never enter `simulators/`
   unscrubbed); the existing allow-list logic is kept.
2. **Fidelity is measured as now** (replay through invoke.py against a fresh materialized state.db,
   compare returned after masking) but the recorded calls are scrubbed the same way the seed is, so
   the comparison happens in one consistent scrubbed namespace. The regeneration retry stays for path
   c only; a and b report a low score with the failing calls and no retry.
3. **Duplicate services.** When two crossing services share tool names (retail vs airline) a recorded
   call is attributed to the service whose tools' `import_path` module matches the module that ran
   (the tool span records `module` when available — capture now writes it, recordings surface it).
   When module is absent, a shared-name call is attributed by episode co-occurrence: to the service
   whose uniquely-named tools appear in the same episode. A service with zero attributed calls is
   dropped.
4. **Cleanup.** `simulators/` holds exactly one directory per crossing service; stale dirs from
   earlier runs are removed under `--force`.

## Consistent scrubbing

`Scrubber.scrub` now scrubs dict KEYS as well as values, so an id used as a dict key (a product
keyed by its 10-digit id) and the same id used as a field value or a tool argument all map to the
same fake — replay against the scrubbed `state.db` reproduces the scrubbed recording. Seed data is
scrubbed with `scrub.scrub` at copy time (parent side, shared instance); `materialize` is
scrubber-free and reads the already-scrubbed source, so `start.sh` rebuilds `state.db` in the image
with no raw data present. Fidelity's db path scrubs the recorded calls before replay+score (the task
path already did via `_scrub_calls`).
