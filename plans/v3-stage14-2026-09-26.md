# v3 stage 14 — the oracle and the ACP server must speak `db`

Stage 13 seeded db services deterministically and the survey produced 6 tau-bench tasks, but two
defects surfaced on the first real document-store target: the oracle failed its own criteria on
5 of 6 tasks, and `touchstone bench` errored inside the container before writing `output.json`.
Both were the same class of omission — a code path that had a `kind == "db"` branch everywhere
except one place — so both fixes are general, not tau-bench-specific.

## Defect A — the oracle never persisted the db writes it replayed

**Root cause.** The oracle's `solution/solve.sh` runs `python -m touchstone.survey.replay
spec.json`, but `task_files._replay_spec` never set the spec's `"invoke"` key. Without it, `replay`
falls back to calling each tool by its mapped import path — `import_path(**arguments)`. A db-service
tool takes an in-process data store as its first argument
(`ReturnDeliveredOrderItems.invoke(data, order_id, item_ids, ...)`) and knows nothing about
`state.db`: the bare call raised (missing `data`), so `state.db` was never mutated. Every task whose
correctness was a `json_extract(...)` state check therefore scored oracle 0 at the gate; only the
one trajectory-only task passed. `agent/invoke.py` (which loads the collections from `state.db`,
calls the tool, and writes the changed documents back) was generated and adapter-checked, and both
fidelity and the packaged agent already routed through it — the oracle solution alone did not.

**General fix.** Thread the container invoke path into the solution spec. When the survey generated
an `agent/invoke.py` (`env_result["invoke"]`), `tasks._build_task` puts `environment.IMAGE_INVOKE`
(`/app/_touchstone/invoke.py`) into the task context and `_replay_spec` emits it as the spec's
`"invoke"`. `replay` then drives every recorded call through invoke.py — load, call, write nested
fields back — exactly as fidelity and the packaged agent do. Falls back to the import path when no
invoke.py exists (HTTP free-function tools, unchanged).

## Defect B — the ACP server crashed before starting on a db service

**Root cause.** `harbor.acp_server._sim_env` (the multi-turn simulated-user path) started every
simulator with `int(sim["port"])`. A `kind == "db"` service has no port, so this raised `KeyError`
inside `build_session`, `new_session` failed, and Harbor reported "Failed to start the ACP session …
`/app/output.json` missing" — every bench/baseline trial errored before a turn ran. `harbor.agent`
already had the `db` branch; the ACP server did not.

**General fix.** Give `_sim_env` the same `db` branch as `agent._start_simulators`: a db service is
started with no port (`start.sh <name>` re-materializes `state.db`) and its env var is pointed at the
container `state.db` path via `db_service.value_for(container_db_path(name), ...)`. Refactored into a
`_start_sim` helper (with `_run_start` monkeypatchable) so both shapes are unit-tested.

## Stage 14b — the ACP server never ran, and a false 0 hid it (0.1.6)

Stage 14's bench line ("6 trials, 0 exceptions, reward 0.500 — real criteria failures, acceptable")
was itself the bug this stage fixes. Re-running with the honesty fix shows those trials had **no
agent trajectory at all**: the ACP server crashed on start with `ModuleNotFoundError: No module
named 'acp'` because `TouchstoneAgent.acp_install` ran `uv pip install … 2>/dev/null || pip install …`
and swallowed the outcome (PEP 668 / no uv / offline), so every multi-turn trial silently scored 0.
The 0.500 was safety-only credit on an agent that never spoke — not a "real criteria failure".

Three class fixes:

1. **Bake the deps at build time.** `environment.py` adds `agent-client-protocol` + `httpx`
   (`_ACP_RUNTIME`) to the image requirements, so the server has them with no runtime install.
   `acp_install` becomes a fallback that, after installing (with `--break-system-packages` on the
   pip leg), runs `python -c "import acp, httpx"` and **raises** with the captured stderr on failure —
   never a silent continue.
2. **`isinstance` for newer bridges.** `TouchstoneAgent` already mixes in harbor's `ACPAgentMixin`
   via `_BASES`; a reload test proves it when harbor is importable.
3. **A missing trajectory is an error, not a 0%.** `jobs.Trial` reads Harbor's `artifacts/manifest.json`;
   a `failed` trajectory entry (or a missing file once a manifest exists), for a non-gate agent, sets
   `reward=None` + error `agent did not run (no trajectory)`. `task_outcomes` prints that in `bench`/`jobs`;
   the review picker skips it, the room opening reports it (`latest_run_errors`), and the survey
   baseline drops it (counts as "not run").
